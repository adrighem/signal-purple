# Track Specification: SQLite Persistence Hardening

## Overview

Harden SQLite storage handling in `signal-purple` by replacing fragile error-string matching with structured SQLite error codes, relieving single-connection pool contention via in-memory metadata caching, and encapsulating database operations within an isolated repository boundary.

## Background

The Signal protocol engine uses an encrypted SQLite database via `presage-store-sqlite` with `max_connections = 1` in WAL mode to eliminate write contention and race conditions during cryptographic ratchet updates. However, the current implementation has several architectural risks:
1. Error classification (`sqlite_store_error_is_transient`) checks for substrings like `"locked"` or `"busy"`, which is fragile against driver upgrades and error format changes.
2. Serializing all database queries through one connection causes reads (such as avatar caching, contact syncing, and group listing) to block time-sensitive outbox message dispatch and acknowledgment writes.
3. Database queries are directly embedded throughout `backend.rs` without a clean storage repository abstraction.

## Functional Requirements

- Transient SQLite error classification must inspect structured error codes from the database driver (`sqlx::Error::Database`, `rusqlite::ErrorCode::DatabaseBusy`, `DatabaseLocked`, or underlying SQLite error codes 5 and 6) rather than parsing formatted error strings.
- Frequently queried read-only metadata (such as group revision numbers and cached contact profile names) must be cached in memory with clear invalidation hooks on sync and update events.
- Direct store manipulation (outbox polling, projection reconciliation, identity change notices) must be encapsulated in a dedicated repository module.
- Retries on transient store errors must maintain the existing exponential backoff invariants.

## Non-Functional Requirements

- Preserve ABI version 7 and existing C/Rust FFI contracts.
- Maintain `max_connections = 1` for protocol-state mutations to guarantee ratchet safety.
- Zero trailing spaces across all modified files.
- Avoid emdash characters in documentation and code comments.
- Keep unit and integration tests passing (`cargo test` and `scripts/check.sh`).

## Acceptance Criteria

- `sqlite_store_error_is_transient` correctly identifies lock and busy errors generated by driver fixtures without substring inspection.
- Cached group revision reads bypass SQLite connection acquisition.
- Invalidation tests verify that contact and group updates immediately refresh cached metadata.
- All store operations are accessible through the storage repository interface.
- Full test suite passes cleanly.

## Out of Scope

- Changing the upstream Presage schema or table layout.
- Opening multiple write connections to the encrypted database.
- Live Signal production network testing.
